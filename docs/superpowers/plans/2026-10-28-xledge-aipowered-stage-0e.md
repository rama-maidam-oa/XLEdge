# XLEdge AIPowered — Stage 0e (shell host) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the XLEdge shell (`AIPowered\XLEdge\XLEdge\XLEdge.dll`): an Add-in Express module that looks to the user exactly like today's XLEdge ribbon, loads the (still empty) core through XLEdge.Loader.Core at startup, reloads it from an offline folder or Release History without restarting Excel, and shuts it down cleanly — the GLSense AIPowered host design, written for XLEdge.

**Architecture:** All decisions live in ADX-free classes inside the shell (`CoreHost` orchestrates start/reload/shutdown through an `IHostUi` seam; `OfflineReleaseScanner` and `ReleaseHistoryRows` hold the window logic) so they are unit-tested. `AddinModule` (ADX) only wires ribbon/Excel events/COM entry points to `CoreHost` and the core. `RibbonController` drives ADX controls by field name. Three WPF host windows (progress, reload source picker, release history) copy the GLSense look with XLEdge text. The core's build now publishes a release zip + manifest, and the shell's build stages it so F5/Excel picks it up.

**Tech Stack:** .NET Fx 4.8.1, Add-in Express 10.1.4703 (ADXAddinModule, ADXExcelTaskPanesManager, ADXExcelAppEvents), WPF, WinForms (FolderBrowserDialog, ImageList), PowerShell 5.1 (post-build), MSTest 3.11.1.

**Spec:** `docs/superpowers/specs/2026-10-28-xledge-hot-swappable-core-design.md` (§2 project mapping, §3, §4, §6 open items for 0e)

5. **Offline folder with several manifests/zips, wrong checksum, not-newer release** → scanner picks newest pair, refuses with the exact message; never stages anything on refusal. Scanner tests.

**Interfaces — Produces:**
